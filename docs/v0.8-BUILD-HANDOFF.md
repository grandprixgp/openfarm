# v0.8 build handoff

For whoever builds openfarm v0.8. Written 16 Nov 2026, with nothing of v0.8 built yet.

**The job:** build what [`openfarm spec v0.8.md`](../openfarm%20spec%20v0.8.md) describes, by hand, on branch `v0.8`, until every item in its "Done" list is a passing test. The spec is the source of truth. This file says where things are, the rules, and the order.

## Where things stand

- Repository: `~/projects/openfarm`. Branch `v0.8` is checked out, cut from `v0.7` (pushed, not merged into `master`).
- v0.7 is finished: 599 tests pass, including the real-cargo runs.
- Python standard library only, tests with `unittest`. openfarm has no dependencies and must stay that way.
- Read first: the v0.8 spec, then `docs/openfarm-internals.md` (module map), then `.openfarm/test-conventions.md`.

## Rules

1. **Stay on `v0.8`.** Don't push, merge, tag, or touch `master` or `v0.7`.
2. **No live model calls.** No real `openfarm run`, no calls to the worker endpoint or to Claude. Everything is proven with the scripted backends, as the existing tests do. The owner runs the first live test.
3. **The worker key** is at `~/.config/openfarm/openfarm.key`. Never read it out, print it, copy it or put it in the repository.
4. **`x-cmd-zdr: 1` goes on every worker call.** Never remove it or add a way round it. A tier never gets its own endpoint, key or headers.
5. **Never use the real state.** Tests work in temporary folders. Nothing may read or write `~/.openfarm/openfarm`, `~/.openfarm/global` or the real `cards-source`. `tests/__init__.py` already points the global library at a temporary folder; keep that.
6. **Swarm off means v0.7.** With `[swarm] enabled = false`, every existing test passes without being edited. If an existing test has to change, say why in that commit's message.
7. **The gates don't loosen.** No new path may pass a red gate, skip a gate, or mark a card done. `never_touch` in `.openfarm/config.toml` binds the farm's workers, not a hand build, so the protected files may be edited, but what the gates check stays the same.
8. **Original work only.** Use this spec's names and wording. Don't copy text, prompts, tool schemas or names from any other product's files or internals.
9. **Commits:** small and often, one step each, every one with the suite green. Messages are casual, lower case, first person ("board store and its lock"), like `git log` on this branch. No `Co-Authored-By`, no attribution lines, no "implemented by".
10. **Heavy runs off `/tmp`.** `/tmp` is a small RAM disk here. Use `TMPDIR=/var/tmp/openfarm-v08` for test runs (`mkdir -p` it first).

## Commands

```bash
cd ~/projects/openfarm
mkdir -p /var/tmp/openfarm-v08
TMPDIR=/var/tmp/openfarm-v08 python3 -m unittest discover -s tests -t .            # about a minute
TMPDIR=/var/tmp/openfarm-v08 python3 -m unittest tests.test_board                  # one file
OPENFARM_E2E=1 TMPDIR=/var/tmp/openfarm-v08 python3 -m unittest discover -s tests -t .   # real cargo, 3 to 4 minutes
```

One Rust bench dry run (`tests.test_bench_run.DryRunTests.test_rust_tasks`, task `rs-config-refactor`) failed once under load in v0.7 with an infrastructure stop and passed on every rerun. If it fails, rerun it alone before looking further.

## Order

Each stage ends with its tests written, the whole suite green, and a commit. Stages 1 to 4 are useful alone, so if the work stops early it stops at a working state.

1. **Effort and tiers.** `RoleModel.effort`, `[tiers.*]`, `effort_param` into the request body, config checks. (Done 2.)
2. **The board.** `openfarm_core/board.py`: posts, numbering, lock, read cursor, wait, cleaning. `openfarm board read|post|wait`. (Done 3.)
3. **The roster and actions.** Members, the checked action functions (`start`, `set`, `hint`, `ask`, `block`, `remove`), `openfarm swarm status|tiers|set|...`. No scheduler changes yet.
4. **The pipeline on the board.** `CardRun` posts every step, makes its worker calls through its card's members (tier and effort per role), and the dossier and run summary gain the team and token tables. (Done 4.)
5. **Seats.** The supervisor through the board for `external`, with `board answer` and the timeout rule; a supervisor backend on a tier. (Done 7, 9.)
6. **Hand-back.** The `HANDBACK` block, `replan_if`, the limit, the `handed-back` stop code. (Done 10.)
7. **Parallel cards.** The collision check, a thread per card, and a lock on everything the spec lists as shared. Check whether `concurrent_builds` is enforced today, and enforce it. (Done 11.)
8. **Coordinators.** The `code` policy first, then the model coordinator with its JSON actions and limits, then the external one through the commands. (Done 5, 6, 8, 13.)
9. **The monitor.** (Done 12.)
10. **Release tidy-up.** README section, `docs/openfarm-internals.md`, the cheat sheet and skills (two copies that must match: `skills/` and `openfarm_core/skill_assets/skills/`), the config template, version `0.8.0` everywhere `0.7.0` appears, the test count in the README and `docs/assets/openfarm-stats.svg`, and the spec's status line. Then the full suite with `OPENFARM_E2E=1`. (Done 1, 14.)

## When something is unclear

Pick the option that keeps the gates strict and leaves swarm-off behaviour unchanged, write it down, and carry on. Stop and leave it for the owner only when it would need a push, the key, real state, a live call, or deleting anything outside the repository.

## What to leave behind

`docs/v0.8-build-log.md`, kept up as the work goes:

- each stage: done, partly done or not started, with its commit;
- the test count and the last full-suite result, pasted;
- "Decisions I made": each place the spec was unclear and what was chosen;
- "Untested": everything nobody has seen working, in those words;
- `docs/v0.8-smoke.md`: the exact commands for the owner's first live run, a DeepSeek-only run (workers, supervisor and coordinator on tier `dsf`) on a copy of one bench task, never on openfarm itself.
