## Decisions I made

- **Stage 1 (`_seat_effort` / `RoleModel.effort`):** When `[swarm] coordinator` or `supervisor` is not `"tier:<name>"` and its `*_effort` key is omitted, the `"max"` default is not validated against a tier's `efforts` list so non-tier seats (`"code"`, `"config"`, `"external"`, `"off"`) do not fail when configured tiers omit `"max"`. Explicit `*_effort` values or `"tier:<name>"` seats are validated against the referenced (or default) tier. If a `"tier:<name>"` seat omits `*_effort` and that tier has `effort_param = ""` with empty `efforts`, its effort resolves to `""` rather than failing on `"max"`.
- **Stage 1 (`[tiers]` in `_TABLE_KEYS`):** Kept `"tiers": set(_TIER_KEYS)` in `_TABLE_KEYS` for schema documentation, while parsing `[tiers.<name>]` sub-tables via `_parse_tiers` so arbitrary tier names are allowed under `[tiers]` and each tier sub-table is checked against `_TIER_KEYS`.
- **Stage 1 (`tests/test_project_config.py`):** Added `"swarm"` and `"tiers"` to `SPEC_KEYS` because `test_the_documented_tables_are_the_only_tables` asserts `set(SPEC_KEYS) == KNOWN_TABLES`.
- **Stage 1 (`globs_overlap`):** Implemented exact product-NFA intersection paired with a segment DFA requiring non-empty repo-relative paths with no leading/trailing `/`, no `//`, and no `.` or `..` segments, matching `compile_glob(normalise(pattern))` semantics.
