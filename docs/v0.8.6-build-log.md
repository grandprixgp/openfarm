# openfarm v0.8.6 build log

I built v0.8.6 on 18 Nov 2026 on top of v0.8.5 (`f25de74`). It came out of two pieces of work:

1. The two v0.8.5 roadmap items: the full 3-repeat bench ([`bench-v0.8.5.md`](bench-v0.8.5.md)) and the 25-card Rust pilot ([`pilot-v0.8.6.md`](pilot-v0.8.6.md)).
2. The live runs that the README's "Not yet tested" list was waiting for.

Every openfarm defect those runs found is fixed here, each with a test that fails on the old code. Cost is reported as token counts and shares, never as dollars.

## Live runs

The runs below used DeepSeek V4.1 Flash workers on Command Code, with `x-cmd-zdr: 1`, effort `high` and `max` on retries. Where a supervisor ran, it was Claude (Opus 5.5) through openfarm's bridge unless the run says otherwise. Nobody ran `agy`.

### Remote installs from GitHub (tree `f25de74`)

Each install was in its own folder, with `HOME` pointed at a temporary folder for `install-skill`.

- **uv:** `uv tool install git+https://github.com/grandprixgp/openfarm` installed 0.8.5, `openfarm --version` worked, and `install-skill --target workspace` wrote the skills.
- **pipx 1.18.19:** `pipx install git+https://…` installed 0.8.5 on Python 3.14.4, and `--version` worked.
- **pip in a venv:** `pip install git+https://…` installed 0.8.5, and `install-skill --target workspace` worked.
- **The plain URL** that SKILL.md showed failed in all three. uv and pipx said the `git+` prefix was missing, and pip downloaded the HTML page and could not unpack it. Fixed in the docs.

### `openfarm run` with no bubblewrap, real Codex (tree `f25de74`)

I hid `bwrap` behind a PATH that links every `/usr/bin` program except bwrap. The task was `py-slug-ends`, with the bench's Codex farm arm.

- **`[micromanager] confine = "bwrap"`** was refused before any model call, with code `acp-confine-unavailable` and the setting to change.
- **The default, `confine = "auto"`,** ran and passed: in-review with 27,404 tokens, 58% worker and 42% supervisor. The run notes say the Codex child is held by its tool flags alone, with no OS boundary.
- **`[runner] confine = "bwrap"`** was refused at start.

### `openfarm drive` on v0.8.5

The command was `openfarm drive --agent claude --seat both --cards 1 --wave --record-verdict` with no `--model`, `--effort` or `--turn-timeout`, on task `py-inventory-remove`.

- **Result:** in-review after 4 driver turns, a clean wave verdict that was recorded, and the hidden tests pass.
- **Tokens:** 30,952, of which 38% worker, 57% supervisor and 5% coordinator. The same run on v0.8.1 took 68,443 tokens over 7 turns.

### `drive` edge cases with the real Claude CLI (tree `f25de74`)

- **Two drives under one name.** A second managed drive is refused by the run lock. A second drive attaching under the same `--driver-name` is refused with the holder's pid, host and start time. The first drive went on to in-review.
- **Ctrl-C.** It ended in 15 s with exit 3, and the card was blocked as `killed`. No process was left behind, the lock and kill switch were gone, and both driver seats had left the roster.
- **A stale lock** after `kill -9` of the whole process group. `status` showed `STALE LOCK`. A new drive printed a take-over note and took the card to in-review (65,360 tokens: 77% worker, 20% supervisor, 3% coordinator).
- **Spend cap on a priced driver** (`--spend 0.03`). It stopped at 0.0593, because the cap is checked after each turn, so it overshot by about one turn. The pending pre-review was recorded as `infra`, not approved.
- **Turn timeout** (`--turn-timeout 180`, with a first turn that waits 200 s). Turn 1 ended with `driver-timeout`, the drive went on, and the card reached in-review.

### TypeScript on a real npm project (tree `f25de74`, then v0.8.6)

The project is `durations`, which I made for this run, with typescript 5.6.3 and prettier 3.3.3 installed by npm. `openfarm adopt --lang typescript` found both.

- **Card TS-2, with `counter_tests = "report"`.**
  - It reached in-review in 5 attempts and 148,222 tokens, 85% of them worker tokens.
  - On attempt 1 the checker wrote a live TypeScript counter-test, `parseDuration(formatDuration(2**53)) === 2**53`. It failed, a real gap against the Done text, and the implementer then fixed it.
  - My own hidden checks passed 7 of 7, and tsc was clean.
  - `prettier --check` failed on the frozen test file. Fixed by `41d3b9e`.
- **Card TS-3, on v0.8.6 with `counter_tests = "reject"`.** This is the same card again.
  - The checker's counter-test, "formatDuration round-trips every whole millisecond", failed on attempt 1. The supervisor upheld it, so the card went back to the implementer, who fixed the gap.
  - The second checker pass accepted the diff, and the card reached in-review in 5 attempts with 88,242 tokens, 75% of them worker tokens.
  - On the branch, my hidden checks pass, `tsc` is clean and `prettier --check` passes, now on the frozen test file too.
  - This is the `reject` path end to end, with a live implementer fixing the bounce.

### `[runner] confine = "bwrap"` on a real build (v0.8.6 tree)

The project was dtolnay/anyhow, with card MECH-1 and no supervisor.

- **Result:** in-review, with the suite and lint run inside the boundary, 69 tests and none lost, and 21,335 tokens.
- **The boundary I observed.** The build ran under `bwrap --unshare-all --share-net --ro-bind / / …`. It had empty tmpfs mounts over `~/.ssh`, `~/.gnupg`, `~/.config/openfarm`, `~/.claude`, `~/.codex`, `~/.gemini`, `~/.config/gh` and the two login folders named by `CLAUDE_CONFIG_DIR` and `CODEX_HOME`, and `--unsetenv` for the session's token variables.
- **On v0.8.5** those two login folders were readable and the token variables were set. Fixed by `76db13f`.

### Standalone `codex-acp` (0.16.0, the latest on npm)

- **What failed.**
  - Through openfarm, on a ChatGPT login, no turn completed. The server's built-in default model, `gpt-5.5`, is refused by the backend.
  - `gpt-6.1-sol` is refused too, once the server's own refusal of any effort setting is skipped.
  - codex-cli 0.166 (the bridge) works on the same login, so the server's bundled Codex core is too old for the current ChatGPT models.
- **What worked.** Under `confine = "auto"`, the server did start inside bwrap for each card.
- **Fixed:** the refused effort and the lost RPC reason (`a96151b`).
- **Not done:** a completed turn. That needs a codex-acp on a current Codex core, or an API-key login.

### The mutation runner on a large project (v0.8.6 tree)

The project was more-itertools: `more.py` has 5,666 lines and the suite has 937 tests. `[gates] mutation = "required"`, and the card was a new `intersperse_every` with its `.pyi` stub.

- **MUT-1.** The mutation gate caught 8 of 8 mutants. The card then stopped on the token budget (528,170 tokens), because `more.py` went into each first implementer brief twice. Fixed by `53dee7e`.
- **MUT-2.** It reached in-review in 7 min 0 s, with mutation catching 7 of 7, and 431,026 tokens, 71% of them worker tokens. My own checks on the branch pass, and the suite stays green.
- **The cost on a file this size** is the whole-file briefs, not the mutation runner.
