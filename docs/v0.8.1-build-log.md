Two reviews and live runs with the real tools then found gaps, and the fix work closed them. The first round is kept below as history, with corrections where a line was not true; the fix work follows it.

Since the first agent's last commit (`3129c0e`): 130 files changed, about 25,900 lines added and 2,900 removed, tests included.

Cost is reported as token shares, never dollars.

## The Fix Work

Two reviews of the first build, and live runs with the real tools (ruff 0.17.5, pytest 9.2.0, cargo-mutants 27.1.0, tsc 7.0.2, prettier 3.10.1, bubblewrap 0.11.1, codex-cli 0.166.0, Claude Code), found gaps. Builders fixed them by area, each on its own branch from `6610f88`, with each new test seen failing on the old code first. The lead merged them and fixed what the live runs found after that. Workers in every live run were DeepSeek V4.1 Flash on Command Code with `x-cmd-zdr: 1`.

**Board, coordinators, flow and CLI.** The review found members posting kinds that only code may post, stop requests that ended a running card in the middle, workers that lost their role's own model, a stall monitor that counted seats as working, late joins that could not steer the run, escalation from an unset effort that went to the lowest rung, hand-back triage that only the code coordinator did, and a human run summary that read the wrong field. Each was fixed with tests (`tests/test_v081_board_*.py`, `test_v081_coord_*.py`, `test_v081_flow_*.py`, `test_v081_cli_*.py`); with the swarm off, a run still behaves as in v0.7. Covered by the offline suite; a live swarm run on the fixed code was not part of the fix work beyond the drive runs below.

**Checker.** The live checker run on `6610f88` showed the second pass naming bugs in prose while openfarm read no counter-test: the brief gave no answer form and the parser expected JSON. Now both passes have a fixed form, an unreadable answer is asked for once more, counter-tests are written as files, run alone and removed with the worktree restored exactly (Python, Rust under real cargo, TypeScript under real node), and the dossier shows the verdict and each outcome. Run live on 24 runs: before, 0 of 24 counter-tests read and 0 of 12 planted bugs caught; on the final code, both passes readable first time in 24 of 24, 12 of 12 planted bugs caught, 2 alarms on clean cards (both real gaps in the bench's reference solutions), 0 wrong counter-tests. Worker tokens are in the [bench report](bench-v0.8.1.md#21-counter-test-gate-calibration). `counter_tests = "reject"` end to end with a live implementer is untested.

**Python and Rust packs, runner.** With ruff installed, the Python pack linted every repo with ruff's default rules, so cards blocked on import order and 20 suite tests failed on a machine with ruff. Now ruff runs only where the project configures it, like pytest. cargo-mutants was called with `--json`, which cargo-mutants 27 takes only with `--list`, and with a `--file` form that was wrong for more than one file; the gate now reads `outcomes.json` from an output folder outside the worktree, treats exit codes 1, 4, 5, 6 and 70 as "did not run", and reports timeouts and unviable mutants apart. A killed or timed-out run could read as green; it no longer can. A named test is judged on every row, with pytest parameter rows counted. cargo's "Blocking waiting for file lock" line made a real test failure look like a machine fault under load, and a killed rustc's "Caused by" block was not matched; both fixed with real output as fixtures. Real ruff, pytest and cargo-mutants were run by the suite and by hand.

**Providers.** The review's first finding was that Codex and Antigravity children could read any file the user could. Now Codex runs with a strict set of `--disable` flags checked against codex-cli 0.166.0, and Codex and Antigravity children run in a bubblewrap boundary that hides every `.git`, the `never_touch` and `forbidden_files` matches and the worker key file (`[micromanager] confine`). Logins are found through `CLAUDE_CONFIG_DIR` and `CODEX_HOME`, and copied back only when checked. A provider/binary mismatch is refused, spend is "measured" only when it is, and `acp status` and `acp probe` never start `agy` unasked. Live with real Codex: tool policy `none` read none of three planted files; `read-only` cannot work inside the boundary on Ubuntu, because Codex's own sandbox cannot start there, and is now refused up front; `off` read all three. A standalone `codex-acp` 0.16.0 needed its whole `node_modules` folder mounted and its model set through config options; after that, handshake and options work, but no turn completed on a ChatGPT login. Claude through the bridge and through the standalone `claude-agent-acp` 0.108.0 answered with tool policy `none` and `read-only`, with the login found through `CLAUDE_CONFIG_DIR`; that run showed cached input was not counted (2 input tokens recorded for a 16,305-token turn), now fixed. One bench card passed with Codex supervising inside the boundary (worker 20.0%, supervisor 80.0%). Everything Antigravity is untested live.

**Drive.** The review found that an aborted drive left the run alive and locked, that a broken driver could hand out approvals and verdicts it was never given, that the driver's spend was not counted, that a turn had no timeout, and that the driver's Codex and Antigravity children had no lock-down. Now an aborted drive ends the board and waits for the run, `run.lock` records its holder and a dead holder on the same host is taken over, unanswered questions go the way `on_external_timeout` says, wave verdicts are recorded only from a real answer and never `clean` on a cut diff, a managed drive's spend counts against its caps, each turn runs in its own process group with a timeout, the driver's children are held like the supervisor's, and a drive can rejoin under the same name. Live on the final code with `py-inventory-remove`: Codex (inside the boundary) and Claude Opus 5.5 each took the card to `in-review` with hidden tests passing and recorded `minor-fix`; worker shares 15.5% and 23.0% with the driver counted. Those runs showed the run's own split left the driver out ("100% worker"), now fixed (`tokens.with_driver`). Untested with a real CLI: Ctrl-C, a stale-lock takeover, a turn timeout, a spend cap stopping a priced driver, and the Antigravity driver.

**TypeScript.** The review found runs that read green without being green (a listed test that never reported, a failing `describe`, a file with no tests), two runners and tool sets that could disagree between check and the card, a syntax fall-back that was not stated, loose scaffold checks, gaps in the banned patterns, and bench scoring of TypeScript tasks by a bare `node --test` run. Now tests run only with `node --test` plus a reporter of openfarm's own, one tool set comes from the base checkout, `tsc` and `prettier` run only where the project has them, syntax-only is stated in the notes and gate records, scaffolds are declarations only, the banned list is wider, mutation settings that cannot work are refused, and adopt handles mixed repos. Real `tsc` and `prettier` were run by the suite, and the TypeScript counter-test path ran with real `node` and scripted answers. TypeScript on a real npm-installed project with a live model writing counter-tests is untested.

**Glue.** `openfarm check` now shows the tooling the card's gates will use, the loaded config reaches the pack (so `--config` is honoured), lint gate records say "syntax only", `acp status` and `acp probe` print the provider-children table and the confinement section, `check --baseline` uses the run's row rule, the checker's first pass has its own form, and each test process keeps its temp files in one folder and removes it. Covered by the offline suite; the first-pass form was followed in 24 of 24 live runs.

### Corrections to the First Build's Claims

- "0 false rejects across 36 live card records" measured nothing (see Stage 4f).
- "Live `cargo-mutants`, `pytest`, `ruff`, `tsc`, and `prettier` ... none of those tools are installed": they are now, and all five were run live in the fix work.
- The first TypeScript pack ran `npm` test scripts; npm, jest, vitest and mocha scripts are now refused.
- Claude supervisor token figures through the standalone `claude-agent-acp` were understated by the cached part; the bridge's were right.

**After the bench.** The first bench round on the fix work (tree `026274d`, one repeat) lost most of its failed cards the same few ways, and three of the same Rust tasks had failed in the first build's bench too. A Rust test writer shown only signatures did not know the crate's name, pulled the source in with `#[path]`, and the copy's unused items failed the lint gate, which the implementer may not fix (or it silenced them, which is a banned pattern). A test build that failed was reported as "not reported by the test binary" with no compiler error, so the retry was a guess; once a supervisor with no tools blamed a corrupted `Cargo.toml` that did not exist. One malformed stub ended the card. Now the Rust brief names the library crate, the unprovable-tests message carries the compiler's errors, the stub note says where a stub lands and not to re-declare a shown symbol, and a refused stub is asked again. Codex's `binary = "auto"` now picks openfarm's bridge when the `codex` CLI is installed. The second round, on the fixed code (`04e58a3`), passed 12 of 12 in both Codex arms and in Claude solo, and 11 of 12 in the Claude farm arm; it is in the [bench report](bench-v0.8.1.md). It showed two more gaps, both fixed: the supervisor's Rust scaffold was refused when a stub kept its parameters used with `let _ = (a, b);` before `todo!()` or was anchored on the end of the block above, and the test writer was told the crate's name but not that a function in `src/config.rs` is `crate::config::f`.

**Outside review.** One read-only review of the whole fix diff (Opus 5.5) found no blockers, 5 larger findings and 15 smaller ones. Fixed: a failed test run that names no failing test read as a green suite; a supervisor the confinement rules refuse degraded every card silently (the run is now refused before it starts, and a card's note no longer says "all passed" over a failed gate); a refreshed login could overwrite a newer one on disk; a second drive could take a held seat by reusing its name, and its end removed the first drive's seats; the Antigravity token check accepted any text. Also fixed: other credentials reached a child through its environment, a timed-out driver turn lost a refreshed login, a correction turn skipped the spend check, the counter-test fallback path was unchecked, the setup probe did not hide the project's files, a Claude child on an API key could not find its key inside the boundary, and a Codex or Antigravity supervisor without prices gave no note. The suite's own log showed one more: a turn whose bridge was stopped mid-way came back as an empty answer, and the test for it asserted in a thread where a failure is lost. That turn is now an error (`acp-turn-cancelled`). The smaller findings that stay are listed as known limits in [HANDOFF](HANDOFF.md#known-limits).

**Second outside review.** After the release was merged, a second read-only review of the whole release (GPT-6.1 Sol through Codex) found no blockers and 11 larger findings; all are fixed. Logins: the compare-and-replace of a copy-back is now one step under a lock, the copy-back goes only to the file the login was read from (a link made or changed meanwhile is refused), and an Antigravity login whose fields were emptied is refused. Gates: only exit code 5 is the finished empty test run (pytest stopped by Ctrl-C prints "no tests ran" too); a counter-test run puts back ignored files that were already there; TypeScript touches with a wildcard that can match `.tsx`/`.jsx` are refused while there is no `tsc`; a TypeScript result row knows its file, so a same-named test in another file no longer reads as mixed. Spend: the cost a standalone server reports is tracked per session, and a driver turn that failed but reported a cost is counted. Drive: a correction turn is a fresh CLI call and is now given the task and the rejected answer again. Scaffold: a Rust scaffold may not carry a constant, a `let` or a macro call beside its stubs, and a keyword does not pass as an unused argument. The review also checked the provider lock-down paths, swarm steering with the seat-holder rules, and behaviour with the swarm off, and found those to hold.
