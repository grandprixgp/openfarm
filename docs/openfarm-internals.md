# Openfarm v0.14.0 Internals

Technical reference for `openfarm_core` (100% Python 3.11+ stdlib-only), optional Textual workbench (`openfarm_tui/`), packaging/bootstrap (`pyproject.toml`, `SKILL.md`, `skills/`, `bootstrap.py`, `acp_setup.py`, `skill_assets/`), the three frontier providers and how their children are held (`adapters/acp.py`, the three bridges, `confine.py`, `logins.py`), driver mode (`driver.py`), six protocol-versioned adapters, Rust/Python/TypeScript/Go language packs (including polyglot `[units.*]`), swarm board/coordinators/tiers (`board.py`, `swarm.py`, `coordinator.py`, `tui.py`), multi-project Studio & Conversational Architect (`automode.py`, `projects.py`, `providers.py`, `findings.py`, `triage.py`, `frontier_review.py`, `doctor.py`), DAG & autonomous factory gates (`dag.py`, `factory.py`, `invariants.py`, `acceptance.py`, `replay.py`, `routing.py`, `timeline.py`), detached daemon & Tailscale Web Companion (`daemon.py`, `web.py`, `notify.py`), 20-table configuration schema, 37 CLI commands, security boundaries, and verification status.

## Module Layout (`openfarm_core/`, `openfarm_tui/` & Packaging)

- `config.py`: Strict TOML loader (`KNOWN_TABLES`, `_TABLE_KEYS`, `Config`, `TierConfig`, `SwarmConfig`, `RoleModel`, `HarnessConfig`) with fail-closed rejection (`ConfigError`) on unknown tables, unknown keys, conflicting keys (e.g. `timeout` vs `timeout_s`), invalid bounds/choices (including `[tiers.<name>]` refusing `endpoint`/`allowed_endpoints`/`key_file`/`headers`, `[swarm]` seat/cap/timeout rules, `RoleModel.effort`, `[harness]` `min_confidence`, `probe_window`, `capture_on`, `editable_surfaces`, `[micromanager] confine`, `[runner] typescript`), invalid policy/globs, or paths escaping the repo root. (Until v0.8.5, `[gates] mutation = "required"` with TypeScript in `languages` was refused at load.)
- `cards.py`: Card data models (`Card`, `TestRef`), `canonical_json`, `hash_value`, `CARD_FIELDS` and `OPTIONAL_CARD_FIELDS` (`unit`, `context_files`, `type_changes`, `replan_if`), and fenced TOML block extractor (`extract_fenced_fields` supporting ` ```openfarm ` and ` ```toml `). Markdown/`+++` TOML parsing (`parse_card_file`) lives in `adapters/files.py`.
- `errors.py`: `StopCode` enum (19 per-card stop codes including `supervisor-reject`, `handed-back`, and `seat-silent`, plus `killed`, `released`, `paused`), `RELEASING_CODES`, and typed exception hierarchy (`AdapterError`, `Refused`, `Infra`, `Invalid`, `Unsupported`, `ConfigError`, `UsageError`, `GateFailure`).
- `protocol.py`: `PROTOCOL_VERSION = 1`, `REQUIRED_OPS` / `OPTIONAL_OPS` for all 6 adapters (`cards`, `runner`, `pack`, `model`, `telemetry`, `micromanager`), and JSON-over-stdio `CmdAdapter` wrappers (`CmdCardSource`, `CmdModelBackend`, `CmdTelemetry`, `CmdPack`). `CmdRunner` lives in `adapters/direct.py` and `CmdMicromanager` lives in `micromanager.py`.
- `globs.py`: Repo-relative glob normalization, `resolves_within` path-traversal guard, exact NFA `globs_overlap(pat1, pat2)` intersection over valid repo-relative paths, and matchers for `never_touch` / `forbidden_files`.
- `git.py`: Git worktree lifecycle (`worktree_add`, `worktree_remove`, baseline reset), `Git.init` (`git init -q -b <branch>`), commit helpers, safe flag/config allowlisting (rejecting arbitrary `-c` / unsafe options), and repo lock coordination.
- `state.py`: On-disk state under `state_dir` (`cards/<safe_id>/<run_id>/`, `runs/<run_id>/`, `checks/<safe_id>/`, `worktrees/`, `baseline-cache/`, `breaker.json`, `config.lock.toml`, `run.lock`, `paused`, `STOP`, and `harness/` via `StateDir.harness(tag="")`), card ID path sanitization (`_safe_id` preventing path traversal), atomic writes, and disk-space floor enforcement (`[state] min_free_mb`). v0.8.1: `run.lock` records `pid`, `host` and `started_at`. `acquire_run_lock` takes over a lock whose holder on this host no longer runs (`stale_lock_holder`, kept in `last_lock_takeover`, printed by `openfarm run` as `note: took over run.lock ...`), with a `flock` on `run.lock.guard` against two takeovers racing. A live holder, a holder on another host, or an old lock without those fields is refused. `openfarm status` and the TUI show a dead holder's lock as stale.
- `budget.py`: Per-card and nightly token/spend/build/wall-clock accounting (`Budget`, `NightBudget` with separate `micromanager_spend`), frontier cost ratio checks, and lease TTL checks. A zero spend limit means no limit (v0.7). `token_split` and `describe_split` give the worker's, the supervisor's and the coordinator's share of a run's tokens, which the run summary (`tokens`), each dossier and the bench report print instead of list-price dollars.
- `edits.py`: Structured `search_replace`, `whole_file`, and `append_stub` edit parser (`parse_edits`) and atomic multi-file `apply_edits` (rolling back all files in a batch if any edit fails or touches a forbidden path). v0.8.1: an `append_stub` block's first non-blank line is the test's whole name; a first line that is code (a declaration, decorator, attribute, import, `raise`/`throw`, or a line ending in `{`, `;` or `):`) is refused at parse time as `bad-block`.
- `mutate.py` (v0.8.5): openfarm's own mutation runner for Python and TypeScript, run as a script with the standard library only. `python_mutants` (syntax-tree swaps, never annotations or docstrings), `typescript_mutants` (token swaps outside strings, templates and comments), `changed_lines_from_diff` (the flow reads the card's diff through `git.py` and passes `--lines`), `spread` (at most `--max`, evenly), a baseline run of the named tests, per-mutant time limits in their own process group, byte-exact restore with the file's modification time, and cached bytecode cleared. It writes `outcomes.json` and a closing line in cargo-mutants' form; `read_outcomes` turns that into the gate's counts. Packs get it through `packs/base.py`'s `OwnMutationMixin`.
- `spawn.py` (v0.8.5): `popen_with_retry` starts a provider program again after 1, 2, 4 and 8 s when it is missing or busy (`ENOENT`, `ETXTBSY`, `EACCES`), for a CLI that updates itself; `OPENFARM_SPAWN_RETRY_DELAYS` overrides the delays. Used by the three bridges and by `driver.py`.
- `briefs.py`: Prompt assembly for `test_writer`, `implementer`, `checker`, and `planner`, incorporating `reference`, `context_files`, rich Rust `signatures()`, `flagged_patterns`, sanitized failure logs, and optional fenced `harness adaptations` (`fence(harness_guidance, "harness adaptations")`). The Python test-writer brief names the runner the project is set up for (`unittest`, or pytest when configured) and says nothing about what is installed. `checker_pass1_brief` and `checker_pass2_brief` end with their answer form, before the hand-back text, and carry the reason when the last answer could not be read.
- `roles/__init__.py`: Role dispatch (`Roles`), plan validation (`parse_plan`, `wants_planner`), and the checker's answer forms and parsers. First pass: `pass1_answer_form`, `parse_pass1` (`RESTATEMENT:`, `CATCHES:` yes/partly/no, `MISSES:`; an old `RESTATEMENT:` marker or bare text still reads). Second pass: `pass2_answer_form`, `parse_pass2` (`VERDICT: accept|changes-requested`, `REASONS:`, `TRACEABILITY:`, `EDGE CASES:` with at least two, then up to `MAX_COUNTER_TESTS = 2` blocks headed `=== counter_test: <name>`, each a complete test file; the old JSON `counter_tests` list, `COUNTER_TEST:` blocks and a bare `{}` still read). `parse_counter_tests` and `parse_restatement` remain as thin wrappers.
- `harness_memory.py`: Recursive Harness Efficiency subsystem (`EDITABLE_SURFACES`, `IMMUTABLE_GATE_KEYS`, `sanitize_lesson_text`, `is_gate_bypass_directive`, `validate_harness_proposal`, `_classify_failure`, `extract_contrast`, `HarnessLedger`, `HarnessLibrary`, `GuidanceSelection`). v0.7: entries carry `scope` (`project` | `general`), `scope_reason` and `origin` (`project` | `global`); `sync_from_global` and `report_to_global` exchange lessons with the global library; selection obeys `learn_from`.
- `harness_global.py` (v0.7): `GlobalLibrary` at `[harness] global_dir` (default `~/.openfarm/global/harness`, or `OPENFARM_GLOBAL_HARNESS`): `entries/g-<hash>.json`, an append-only `ledger.jsonl`, a `flock` lock, nothing created until a write. `add` keeps only a lesson's travelling fields (no evidence or card IDs) and records each source project; `report` stores per-project `applied`/`helped`/`hurt`/`neutral`/`vetoed`; `retire` and `restore`. The rules: `should_promote` (general, active, helped >= 3, hurt < helped), `should_veto` (hurt > helped) and `retire_reason` (2 or more vetoes, or a negative combined score).
- `harness_scope.py` (v0.7): `project_markers` (the project's name, tracked paths, file names, stems of 5+ characters, and distinctive Python/Rust definition names), `scope_of` (a lesson naming a card, a file in its patch or any marker is `project`, whatever it claimed) and `global_eligibility` (no fixed-rule cues, project lessons, imports, supervisor bookkeeping, text over 400 characters, code blocks, gate-bypass directives, assertion leaks or named files).
- `micromanager.py`: Supervisory orchestration (`Micromanager`, `NullMicromanager`, `ScriptedMicromanager`, `CmdMicromanager`, `ClaudeAcpMicromanager`, `ExternalMicromanagerBackend`, `TierMicromanagerBackend`, `SUPERVISOR_OP_EXPECTS`, `open_micromanager`) implementing 6 ops (`shape_and_plan`, `scaffold_contract`, `coach`, `adjudicate_checker`, `triage_and_review`, `reflect_harness`), plus `self.harness_context` forwarding. Enforces thread-safe `MicromanagerBudget` (`max_calls_per_card`, `tokens_per_card`, `spend_per_night`), strips/blocks edit blocks outside contracts (`_strip_edit_blocks`), validates production `todo!()`/`unimplemented!()` stubs (`_valid_production_scaffold`), validates TypeScript scaffolds as declarations and one-throw bodies only (`typescript_scaffold_problem`), and sanitizes paths (`_validate_safe_path`). `open_micromanager` refuses a `[micromanager] binary` that names another provider than the adapter (`acp-provider-mismatch`) and passes the `confine` settings on.
- `confine.py` (v0.8.1): how a provider's child is held. `codex_tool_flags(tool_policy)` is the Codex `--disable` set (see below). `decide`, `hold_for` and `bridge_plan` pick flags, boundary or a refusal from the provider, the transport (`bridge`, openfarm's own bridge starting one CLI child per prompt, or `server`, a standalone ACP server), the tool policy and `[micromanager] confine`. `bwrap_status` checks once per `bwrap` path that bubblewrap really runs; `nested_status` checks whether a sandbox can start inside the boundary. `boundary_argv` builds the bubblewrap argv. `off_note`, `flags_only_note` and `hold_note` are the texts the run's notes carry. `end_process_group` ends a child's whole process group (SIGTERM, then SIGKILL).
- `logins.py` (v0.8.1): `login_place(provider)` finds a login (`CLAUDE_CONFIG_DIR`, then `$HOME/.claude`; `CODEX_HOME`, then `$HOME/.codex`; Antigravity under `$HOME`). `isolated_login_env` points the child's `CLAUDE_CONFIG_DIR` / `CODEX_HOME` inside its isolated home. `sync_back` is the one copy-back of a refreshed login (see [Logins](#logins-and-the-copy-back)).
- `adapters/`:
  - `files.py`: `FileCardSource` (`parse_card_file`) reading `+++` TOML/Markdown cards (including `replan_if`), protected with per-source locking and atomic card/checkbox updates.
  - `direct.py`: `DirectRunner`, `CmdRunner`, and `BuildLimiter` (`[budget] concurrent_builds`, pausing card wall-clock while queued) executing build/test subprocesses with safe env scoping (`[runner.env]`) and timeout/signal reporting. `classify` reads a run as infra on `INFRA_PATTERNS` (a killed compiler, including cargo's "Caused by ... (signal: N)" block, disk or memory errors, download failures, an internal compiler error) and on cargo's "Blocking waiting for file lock" only when that is the last thing cargo said.
  - `openai_compat.py`: `OpenAICompatibleBackend` & `ScriptedBackend` with endpoint allowlist validation (`allowed_endpoints`), key-file loading, `[model] headers` (`x-cmd-zdr: 1`), `effort`/`effort_param` payload injection, thread-local usage tracking, and retry handling for HTTP `429` and `5xx` responses.
  - `jsonl.py`: `JsonlTelemetry` writing structured JSONL telemetry events (`CARD_FIELDS` includes `harness_revision`, `harness_cues_applied`, `harness_lessons_added`).
  - `acp.py`: Multi-provider `ClaudeAcpAdapter` (`ACP_PROVIDERS = ("claude", "antigravity", "codex")`, `ACP_ADAPTER_NAMES = ("claude-acp", "antigravity-acp", "agy-acp", "codex-acp")`) speaking Agent Client Protocol v1 (NDJSON JSON-RPC 2.0 over stdio). `resolve_acp_command` turns `[micromanager] binary` into an argv (see [Binary resolution](#binary-resolution)); one resolved provider then decides argv, environment, home and copy-back, and `check_provider_matches` refuses a binary that names another provider. `_sanitised_env` strips host credentials and provider API keys and, with `isolate_home = true`, points `$HOME` at a scratch folder with the login copied in. Strict non-interactive `authenticate` handshake, `_apply_antigravity_config_options` (also used for a standalone Codex server's `configOptions`), `Refused("acp-auth-required")` mapping, strict capability denial, and read-only permission handling judged against each session's own folder. `provider_prices_spend` is true only when the provider reports cost (Claude) or a per-1k rate is set. A standalone ACP server is wrapped in the boundary at the adapter's folder, and a session outside it, or inside a hidden folder, is refused. Usage reported with cached input apart (`cachedReadTokens`, `cachedWriteTokens`) is counted as input.
  - `claude_native_acp.py`, `agy_native_acp.py`, `codex_native_acp.py`: Pure-stdlib ACP v1 bridges. Claude: `claude -p --output-format json --no-session-persistence --disable-slash-commands --strict-mcp-config --permission-prompts none --permission-mode dontAsk` with `--tools ""` (tool policy `none`) or `--tools Read,Glob,Grep` plus the deny list (`read-only`); never `--bare`, so OAuth works. Antigravity: `agy --output-format json --sandbox --disable-slash-commands ... -p <prompt>`, refusing before the spawn a prompt over Linux's one-argument limit of 131072 bytes (`agy-prompt-too-large`). Codex: `codex exec --json --ephemeral --skip-git-repo-check --ignore-user-config --ignore-rules -s read-only <tool flags> -C <dir> -`. Every bridge refuses an unknown tool policy, wraps its CLI child in the boundary when the hold says so, runs it in its own process group, and ends every child's group when it is stopped (SIGTERM or SIGHUP) or reaches end of input.
- `packs/`:
  - `base.py`: `Pack` abstract contract (`commands`, `parse_list`, `parse_tests`, `parse_mutation`, `error_signature`, `classify_paths`, `signatures`, `edit_formats`, `apply_edit`, `append_stub`, `format`, `format_check`, `patterns`, `mutation`), `UnsupportedPack`, and `pack_for` factory (`rust`, `python`/`py`, `typescript`/`ts`). Also the language-neutral `apply_text_edit` and `added_lines_from_diff`. v0.8.1 adds `prepare_worktree` (readies another checkout for a run; TypeScript links `node_modules`), `tooling_summary` (what `openfarm check` and each card record show), `gate_evidence` (extra evidence on lint gate records) and `row_file` (the file a result row came from, when the pack can tell). Every `pack_for` call that has a loaded config applies it (`apply_settings`), so `--config` reaches the pack.
  - `typescript.py` (v0.8.1): `TypeScriptPack`. Tests run only with `node --test`, with TAP plus a second openfarm reporter that reports every result with its file, each file's static listing and the exit code. A listed test that never reported is a red row (`never-reported`), a file that registered no tests is red, a failed `describe` (its body throws or a hook fails) is a red row named after the suite, and a non-zero exit with nothing red is a red row. The footer is read only from the final top-level plan. `resolve_tooling` decides the tools in the base checkout (found through `.git` -> `commondir` from a card worktree): its `node_modules/.bin` first, then `PATH`. `tsc --noEmit` runs only with a `tsconfig.json`; otherwise the type check is node's type stripping ("syntax only", stated in the notes and in the eligibility and lint gate records). `prettier` runs only when the project configures it (a config file or a `prettier` key in `package.json`). A test script that is not `node --test` is refused (`unsupported-test-runner`). `link_node_modules` gives a card worktree a real `node_modules/` folder holding one symlink per entry of the base's git-ignored `node_modules` (made only when git ignores it there, and removed by `git worktree remove` without touching what it points at). A test file is a name ending `.test.*`, `.spec.*` or `_test.*` with an extension node runs (`.ts`, `.mts`, `.cts`, `.js`, `.mjs`, `.cjs`); one rule (`is_test_file`) drives eligibility, discovery, the list script and `classify_paths`. Signatures by a lexical scanner that knows when `/` starts a regex and keeps decorators with their class. Banned: `@ts-ignore`, `@ts-expect-error`, `@ts-nocheck`, `eslint-disable`, coverage ignores (`c8`, `istanbul`, `v8`, `node:coverage`), `debugger`, `node:inspector`, `.skip(`/`.todo(`/`.only(` and `skip:`/`todo:`/`only:`/`expectFailure:` test options, `child_process`, `process.binding`/`dlopen`, dynamic `import(`/`require(` of anything but a string literal, `fetch(`, the `node:http`/`https`/`http2`/`net`/`dgram`/`tls`/`dns` modules, `undici`, `XMLHttpRequest`/`WebSocket`/`EventSource`/`sendBeacon`, any `eval` reference, `Function(`, `node:vm`, `globalThis[...]`/`global[...]`, empty catches, and not-implemented throws in production code. Build-output folders (`dist`, `build`, `target`, `.next`, `.nuxt`, `.turbo`, `coverage`, `.cache`) are skipped only at a unit root. Mutation through `mutate.py` (v0.8.5).
  - `python.py` (v0.6): `PythonPack` for Python 3.11+ repositories. `unittest` unless the repository configures pytest (`detect_runner`: `pytest.ini` or `[tool.pytest.ini_options]`); parses `unittest -v` and `pytest -v` per-test lines and footers (no footer is infra, an import failure is a compile error, a pytest "no tests ran" summary is a finished empty run); lists tests without running them; an `ast`-only syntax check as lint, plus `ruff check` and `ruff format` (with `--no-cache`, and `--config` when the project's file sits outside the worktree) only when the project configures ruff (`[tool.ruff]` in `pyproject.toml`, `ruff.toml` or `.ruff.toml`, `detect_ruff_config`) and it is installed, otherwise one note saying why; body-free `ast` signatures; `raise NotImplementedError` stubs; Python banned patterns (bare `except:`, swallowed exceptions, `# noqa`, `# type: ignore`, debugger calls, skips, process, network and `eval`/`exec`, production stubs). `row_file` maps a pytest or unittest row to its file. Mutation through `mutate.py` (v0.8.5).
  - `rust.py`: `RustPack` implementing rich `signatures()` (structs, enums, traits, type aliases, consts, statics, unions, `mod`, `impl` blocks), `cargo fmt`, split stdout/stderr Cargo error & crash signal parsing, `--test <stem>` execution for counter-tests, and the mutation gate's `cargo mutants --no-times --colors never --output <dir> --in-diff <card.diff> --file <f> ...` (diff-scoped since v0.8.7, whole-file on `test-backfill`). The output folder is `card_layout/gates/mutation/N/` (a private temp folder when the flow sets none), never the worktree. `read_mutation` reads the exit code first (0, 2 and 3 are results; 1, 4, 5, 6 and 70 mean the tool did not run, `Invalid("mutation-not-run")`), then `mutants.out/outcomes.json` (`total_mutants`, `caught`, `missed`, `timeout`, `unviable`), falling back to the summary line `N mutants tested: a missed, b caught, c unviable, d timeouts`.
  - `go.py` (v0.9.0): `GoPack` for Go repositories (`go.mod` detection), executing `go test -json`, `go vet`, `gofmt`, Go banned patterns, and `mutate.py --lang go` support.
  - Note (v0.9.0): `TypeScriptPack` supports `[runner] typescript = "node" | "vitest" | "jest"` with JSON output parsing and `adopt` auto-detection; polyglot repositories configure per-unit packs under `[units.<name>] language = "rust" | "python" | "typescript" | "go"`.
- `gates/`:
  - `eligibility.py`: `check_eligibility` enforcing 9 `KNOWN_CATEGORIES`, `max_files`, `max_units`, `require_reference`, `context_files` bounds (`max_context_files`), `type_changes` (`allow_type_changes`), multi-file `new_symbols` rules (permitted when `type_changes = true` or `scaffold_contracts = true`), `never_touch`/`forbidden_files` intersections, and card hash checks. TypeScript rules (v0.8.1): `typescript-tools` (a recorded tool is missing), `typescript-test-runner` (the test script is not `node --test`), `typescript-jsx-unchecked` (a card touches `.tsx`/`.jsx` while the type check is syntax only) and a test file that node cannot run. `EligibilityResult.info` carries the TypeScript tooling decision. The known-failing rule compares exact names, so a card whose test has every parameter row on `known_failing` passes it (see [Known limits](HANDOFF.md#known-limits)).
  - `checks.py`: Deterministic gate helpers including `revert-check` against `base + frozen-tests` (after formatting), mutation kill-rate enforcement (`mutation_required_for`; the rate is caught over caught plus missed when the pack reports them, with timed-out and unviable mutants left out and named), counter-test bounce-back handling, `workspace_lint`, `baseline_cache`, `catch_up`, `extra` custom gates, and circuit breaker tracking keyed by real card IDs in `breaker.json`. v0.8.1: `rows_for_test` (a row belongs to a named test if its name is exactly the name, or the name followed by a parameter id `[...]` when the card's name has no `[` of its own; rows from another file are left out when the pack can tell) and `combined_status` (`not-run`, the one status, or `mixed`). `suite_green` returns infra for any run the runner classed as infra, whatever the parser found; pass-after requires every row of a named test to be `ok`.
- `selfhost.py` (v0.6): `unpinned_reason` refuses a real run when the running `openfarm_core` sits inside the repository or its `state_dir` (a card could edit its own judge); `orchestrator_identity` gives the version, path and commit printed as `Judged by ...` at the top of every dossier. Git goes through `git.py`.
- `adopt.py` (v0.6): `detect_language` (a Cargo or Python manifest decides, as in v0.8; Cargo and Python together is `ambiguous-language`; a `package.json` or `tsconfig.json` beside them is noted, and `--lang typescript` adopts the TypeScript side), `adopt_config_text`, `adopt_project` (writes three files, never commits; refuses `not-a-git-repo`, `already-adopted`, `dirty-worktree`, and for TypeScript `unsupported-test-runner` before anything is written), `typescript_adopt_checks` (records `typescript_typecheck` and `typescript_format`, and names enums, namespaces, parameter properties and extensionless relative imports, which node's type stripping cannot run), `baseline_known_failing` (runs the suite once with cargo building into the state folder; `suite-does-not-compile` and `suite-did-not-run` refuse before anything is written) and `propose_known_failing`. Proposed red tests go in a comment above `known_failing`, never into it.
- `config_template.py` (v0.6): `render_config`, the one `.openfarm/config.toml` template behind `openfarm init` (Rust, `never_touch = ["src/invariants.rs"]`) and `openfarm adopt` (Rust, Python or TypeScript). The TypeScript template forbids `package.json`, the npm, yarn and pnpm lock files, `.npmrc`, `tsconfig.json` and `node_modules`, and writes the `[runner]` TypeScript keys.
- `bench.py` (v0.6): `load_task` (`bench/<task>/task.toml` with `id`, `language`, `category`, `card`, `hidden_tests`; optional `repo/` and `script.json`), `score`, `render_report`, `load_arm` and `arm_config_text` (an arm replaces `[model]` and `[micromanager]` and the two `[adapters]` keys of the task's adopt config), `run_once` (fresh copy of `repo/`, `git init`, the card committed, `openfarm run` in a subprocess, then the hidden tests copied onto the card's branch and the whole suite run) and `run_bench`. `--tasks` (alias `--dir`) and `--out` are resolved to absolute paths. A run that never started gets `error` and `stop_code`, is kept out of the counts, and is listed in the report's "Runs that did not start" table. A TypeScript task passes only when the suite with the hidden files named explicitly is green by the pack's parser, node exited 0, and every hidden file reported a passing test and no failed or ignored one (`_score_typescript`). `bench/` ships 12 tasks (6 Rust, 6 Python, all four categories) and `bench/arms/*.example.toml` (Claude, Codex and Antigravity arms).
- `adapters/claude_worker.py` (v0.6): `ClaudeAcpWorkerBackend`, the worker backend for an ACP `[adapters] model` (`claude-acp`, `codex-acp`, `antigravity-acp`; the bench's `solo` arm). One fresh ACP session per call, tools off, in an empty private folder made on first use and removed on close (v0.8.1; before, the state folder), connection settings from `[micromanager]`, the model per role from `[model]`; a `max_tokens` stop maps to `finish_reason` `length`. `prices_spend` follows `provider_prices_spend`.
- `dossier.py`: Structured per-card artifact and Markdown/JSON dossier writer (including micromanager calls, scaffolds, coaching hints, verdicts, and optional `harness` summary). v0.8.1: a "Checker, second pass" line sits under the run line; section 6 gives the first pass's would-it-catch answer and misses (labelled as a model's opinion that blocks nothing), the second pass's verdict, reasons, whether it was asked again and why, each counter-test's outcome (failed with the first lines of its output, passed, dropped or not run with the reason), and the traceability and edge cases. Model text is shown in `text` blocks with its fences broken up. "Not checked" says when a pass could not be read.

## Providers and Confinement (v0.8.1)

### Binary resolution

`[micromanager] binary` (and `openfarm acp --binary`) resolves per provider:

| Provider | `binary` | Runs |
| --- | --- | --- |
| Claude | `"auto"` | `claude-agent-acp` if on `PATH` (npm `@agentclientprotocol/claude-agent-acp`), else openfarm's bridge over `claude` |
| Claude | `"claude"` | openfarm's bridge over `claude -p` |
| Codex | `"auto"`, `"codex"` | openfarm's bridge over `codex exec` when the `codex` CLI is on `PATH`, else a standalone `codex-acp` if that is |
| Codex | `"codex-acp"` | a standalone `codex-acp` if on `PATH`, else openfarm's bridge over `codex exec` |
| Codex | `"codex-exec"` | always openfarm's bridge over `codex exec` (recommended) |
| Antigravity | `"agy-print"` | openfarm's bridge over `agy -p` |
| Antigravity | `"auto"`, `"agy"`, `"antigravity-acp"` | `antigravity-acp` if on `PATH`, else `agy acp` (agy's own ACP server) |

Anything else runs as given. A binary whose program names another provider than the adapter is refused (`acp-provider-mismatch`); a model name in the arguments never counts.

### How a child is held

`confine.decide` gives one of: `flags + boundary`, `boundary`, `flags`, `nothing` or `refused`.

| `confine` | Claude | Codex, bridge, tool policy `none` | Codex, other | Antigravity |
| --- | --- | --- | --- | --- |
| `"auto"` (default) | nothing (Claude Code's own settings) | flags, plus the boundary when `bwrap` works | boundary, or refused | boundary, or refused |
| `"bwrap"` | boundary, or refused | flags + boundary, or refused | boundary, or refused | boundary, or refused |
| `"off"` | nothing | flags | nothing | nothing |

"Codex, other" is tool policy `read-only` through the bridge (flags + boundary) and any standalone Codex ACP server (boundary). Codex `read-only` inside the boundary is also refused when `nested_status` says a sandbox cannot start inside it, because Codex runs each shell command in a bubblewrap of its own; on Ubuntu with `kernel.apparmor_restrict_unprivileged_userns = 1` it cannot (`bwrap: No permissions to create a new namespace`). The refusal names the ways out: tool policy `none`, the Claude provider, or `confine = "off"`.

- **Codex flags** (`codex_tool_flags`), checked live against codex-cli 0.166.0. Tool policy `none`: `--disable` for `shell_tool`, `unified_exec`, `apps`, `plugins`, `multi_agent`, `browser_use`, `computer_use`, `image_generation`, `view_image`, `multi_agent_v2`, `goals`, `sleep_tool`, `code_mode_host`, `tool_suggest`, `skill_search` and `hooks`, plus `-c web_search="disabled"`, after `-s read-only`. With these, Codex ran neither a file read nor a web fetch and still answered. `read-only` keeps `shell_tool`, `unified_exec` and `code_mode_host` (its shell needs the host) and turns off the rest.
- **Claude** under `auto`: tool policy `none` is `--tools ""`; `read-only` is `--tools Read,Glob,Grep` with a deny list built from `never_touch` and `forbidden_files` (with the defaults). Through the standalone `claude-agent-acp`, openfarm's permission handler allows a read only inside the session's own folder (the adapter's folder when a session has none), never in `never_touch` or `forbidden_files`, and rejects a request naming another session. openfarm puts no OS boundary around a Claude child under `auto`.
- **Antigravity**: agy has no documented no-tools flag, so tool policy `none` is agy's own `--sandbox` plus the boundary. It is not "no tools".
- **The boundary** (`boundary_argv`) is bubblewrap with `--die-with-parent --unshare-all --share-net --new-session`. Read-only: `/usr` and the merged-usr links, a short list of `/etc` entries (resolver, TLS roots, `passwd`/`group`, the loader cache, time zone), the program's install tree found from its real path (for a node program, the whole `node_modules` folder it sits in; for a script, its interpreter), `confine_read_roots`, and the session folder. Inside the session folder every `.git` and every `never_touch` and `forbidden_files` match is hidden (a folder by an empty read-only tmpfs, a file by `/dev/null`), and so is the worker key file if it falls inside a mounted folder. Read-write: the isolated home and a private `/tmp`. The root is remounted read-only, so the child writes only in its home and `/tmp`. The real home, the state folder, other worktrees and the key file are never mounted. A session folder or a home that holds the real home is refused. The network is shared, because the model call needs it.
- **`confine = "off"`**: no boundary. The child can read whatever your user can; only its own tool settings limit it. The run's notes, `acp status` and `acp probe` say so. Codex keeps its tool flags under `off`.
- **Notes**: a run whose ACP worker, supervisor or coordinator child is not confined gets one note per text in `run.json` `notes` and the human output (`off_note`, or `flags_only_note` when Codex runs on flags because `bwrap` is unusable).
- **Process groups**: each bridge runs its CLI child in its own process group and ends every child's group when the bridge is stopped or reaches end of input; the driver does the same per turn.

### Logins and the copy-back

The login is found with `logins.login_place`: `$CLAUDE_CONFIG_DIR` (its `.credentials.json` and `.claude.json`), then `$HOME/.claude`; `$CODEX_HOME`, then `$HOME/.codex`; Antigravity's token under `$HOME`. With `isolate_home = true` it is copied into the scratch home, and the child's `CLAUDE_CONFIG_DIR` (`<iso>/.claude`) and `CODEX_HOME` (`<iso>/.codex`) point inside it; the real ones are never handed on. `logins.sync_back` copies a refreshed login back only to the place it was read from, and only when:

- the isolated copy is a regular file, opened with `O_NOFOLLOW` on every folder and the file, under a size cap (1 MiB; 64 KiB for Antigravity);
- it has the provider's shape: Claude, a `claudeAiOauth` object with an access token that does not lose a refresh token the old one had or expire earlier; Codex, `tokens.access_token` with the same `tokens.account_id` and `auth_mode`, a `last_refresh` not older, and no lost refresh token (a non-OAuth original is not overwritten); Antigravity, non-blank UTF-8 text with no NUL, and a JSON object if the old one was.

It writes atomically at mode 600 and keeps the previous credential as `<name>.openfarm-backup`. A refused copy is noted with its reason, never its content.

### Spend

`provider_prices_spend` is true only when the provider reports a cost (Claude does; `codex exec --json` and `agy` report none) or a per-1k rate is set. For the worker backend (`cli._backend_prices_spend`, `[model]` rates), a run without one says `spend_measured: false` and adds the note that the spend caps cannot fire. A Codex or Antigravity micromanager's spend is priced from `[micromanager] cost_per_1k_in` / `cost_per_1k_out`; without them it reads zero, its `spend_per_night` cannot fire, and the run's notes say so (`cli._unpriced_supervisor_note`). A drive with an unpriced driver notes that the caps cannot fire for the driver.

## Driver mode

`driver.py` holds board seats with a CLI agent. Each turn's prompt carries what the driver needs (board state, open questions, and for `--wave` the card's dossier and up to 24,000 characters of diff); the child reads nothing from disk.

- **Children.** `driver_hold` uses tool policy `none` and the bridge transport through `confine.hold_for`. Claude: `claude -p ... --tools ""`, in the repo when not confined, as before. Codex: `codex exec ... -s read-only <none flags> -C <private folder> -`. Antigravity: `agy --output-format json --sandbox --disable-slash-commands -p <prompt>`, refused before the spawn over 131072 bytes. Every child but an unconfined Claude runs in an empty private folder (`openfarm-drive-empty-*`, mode 0700), removed on close. A refused hold returns a refused payload (`acp-confine-unavailable`) before the board, run folder or lock is touched; the CLI exits `1`. The payload's `confine` block says how the child was held.
- **Turns.** Each turn runs in its own process group and is ended on timeout (`--turn-timeout SECONDS`, default 180, a positive finite number), on an abort, and after a normal exit, before its isolated home is removed. A failed turn (`Infra` or `Refused`) goes into `driver_errors` and that turn falls back; the drive goes on.
- **No made-up answers.** A question or card event the driver did not really answer gets code's own seat time-out post, and the run's waits apply `[swarm] on_external_timeout`: `block` gives `seat-silent`; `fallback` records the op as degraded and moves on by code policy. The driver reads finished and stopping cards through `swarm._card_progress`, counts plan, `struggling` and `stall` events only from code's own posts, and answers only `gates` questions that code posted.
- **Ending.** Whether the drive returns or raises (Ctrl-C included), `_end_drive` ends the board (`driver-aborted`), writes the kill switch if it is not there, waits for the run thread with no cap, removes the kill switch only if it wrote it, and marks the members this drive joined `removed` with `left_seat`, only while they still record this drive as their holder. If that wait is interrupted, the kill switch stays and the message says to clear it with `openfarm resume --clear-kill`. Clean-up errors are reported (`cleanup_problems`, `ok: false`), never swallowed.
- **Spend.** Each turn's tokens and cost are split by the part it worked for (`coordinator`, `supervisor`, `review`) and booked on `driver-coord` and `driver-sup`. A managed drive's night budget (`_DrivenNightBudget`) counts the driver's cost and the running cards' live spend against `--spend` / `spend_per_night`, so the cap stops the run's claims too; past the cap the driver takes no more turns (`spend_stopped`) and skips the wave. An attached drive (`--run ID`) says its cost is not counted against that run's caps. `run.json` gains `driver`, `driver_spend` and `tokens.with_driver` (the run's token split with the driver's turns counted); the payload gains `driver_spend`, `driver_spend_measured`, `driver_tokens_estimated`, `driver_by_part`, `spend_cap`, `spend_stopped`, `run_spend`, `driver_counted_in_run`, `run_tokens`, `timeouts`, `driver_errors`, `notes` and `confine`.
- **Logins.** Found with `logins.login_place` and copied back only through `logins.sync_back`.
- **Wave verdicts.** `--wave --record-verdict` writes `verdict.json` only where none exists (written to a temp file and linked into place), with `by: driver/<agent>`, `run`, `review_tokens` measured from the reviewer's own turns (never the model's claim), `review_tokens_estimated` and `diff_truncated`. A `clean` on a cut diff is not recorded (`proposed_verdict: clean`). An unusable answer, no turn left or a failed turn records nothing (`reviewed: false`, `not_reviewed_reason`). `openfarm verdict` overwrites a driver's verdict and writes `by: reviewer`.
- **Rejoin.** A drive that ended can join the same run again under the same `--driver-name`; `swarm_join` lets it take its seat back if nobody else holds it. A caller that keeps a seat (`new_seat_holder`, used by `openfarm drive`) is recorded on the member as `holder` (`pid`, `host`, `since`, `token_sha256`; the token itself stays in the drive's memory). An active member is re-joined only by its holder, taken over only when the holder's pid is dead on this host, and never changes owner kind through a re-join; the check and the write happen under one board lock (`Board.transaction`).

## Gates and records changed in v0.8.1

- **Fail-before and pass-after** judge every row of a named test (`rows_for_test`, `combined_status`). A `mixed` name on base fails fail-before ("reported both failing and not failing on base, so they prove nothing", `mixed_on_base`) and the card blocks `tests-unprovable`. Pass-after needs every row `ok`. The rows are recorded in the gate records. `check --baseline` uses the same rule and also refuses a named test that is skipped or expected to fail on base (`ignored_on_base`); a test not yet on base is fine, because the test writer adds it.
- **Infra runs.** `suite_green` and pass-after return infra for any run classed infra; pass-after raises `Infra("pass-after-infra")` instead of counting an attempt. A counter-test run with missing footers reads every counter-test as not run.
- **Checker, first pass.** Asked once more when unreadable (`responses/checker-pass1-again.json`). `CardRun.checker_pass1` (readable, problem, form, catches, misses, asked_again, first_problem) is in the `checker-pass1` gate evidence. Only the restatement is compared with the tests; an unreadable first pass blocks nothing, even under `reject`.
- **Checker, second pass.** Asked once more when unreadable (`responses/checker-pass2-again.json`). Still unreadable: under `report` the `checker-pass2` gate passes with "no counter-test ran, nothing was checked" and the record gets `counter_tests.unreadable = 1`; under `reject` the gate fails and the card blocks `checker-reject`. The verdict decides nothing; only a failing counter-test does. The gate detail states the verdict and the counts.
- **Counter-tests.** Each is written as a new file (a path the model names, if it is a test path that does not exist yet; otherwise `tests/test_openfarm_counter_N.py`, `tests/openfarm_counter_N.rs` or `tests/openfarm_counter_N.test.ts`, inside the unit's folder when it has a manifest), run alone, and removed. Outcomes: `failed` (last 4000 characters kept, plus the first lines from the first failure), `passed`, `dropped` (did not compile, could not be collected, or the run did not finish) and `not-run` (the runner reported no test by that name). Every outcome goes to `gates/counter-test-N.json`. Before each run HEAD, the branch, dirty and untracked files' bytes, the ignored set, every ignored symlink and the existing folders are recorded; afterwards the branch is checked out again if it changed, `reset --hard` to the old HEAD, the files written back, new ignored files removed, links put back (the pack sets `node_modules` up again if an ignored entry is gone), and HEAD and `git status` compared. Under `reject`, a failing counter-test goes to `adjudicate_checker` when the micromanager is on (`dismiss_false_reject` lets the card go on), else back to the implementer once with the counter-test output; still failing, the card blocks `checker-reject`.
- **Mutation.** `mutation_summary` gains `timeout`, `unviable` and `judged`. A tool that did not run is recorded with its exit code ("the mutation tool did not run: cargo-mutants exited 4, ..."), which blocks as `mutation-cap` when the gate blocks.
- **Revert-check and catch-up** trial checkouts are readied by the pack (`prepare_worktree`), so a TypeScript card's checkout has its linked `node_modules`.
- **Records.** Every card record carries `tooling`. `openfarm check --json` has `tooling` and, for TypeScript, `eligibility.info.typescript`. TypeScript lint and workspace-lint gate records carry `typecheck`, `syntax_only` and a note. `verdict.json` has `by` (`reviewer` or `driver/<agent>`). `run.json` has `spend_measured`, `notes`, and in a driven run `driver`, `driver_spend` and `tokens.with_driver`.
- **Bench records.** A run that never started has `error` and `stop_code`.

## Recursive Harness Efficiency Architecture

Inspired by `google-research/harness2` (`arXiv:2610.14224`), `openfarm_core/harness_memory.py` keeps all learned state outside the git repository under `<state_dir>/harness/` (`StateDir.harness()`, or `[harness] dir`):

1. **Invariants & Editable Surfaces**:
   - `IMMUTABLE_GATE_KEYS` blocks any lesson or `proposed_patch` from touching deterministic verification gates, policy lists, touches, or budgets (`cargo_test`, `clippy`, `mutants`, `diff_check`, `revert_check`, `counter_tests`, `forbidden_files`, `never_touch`, `touches`, `eligibility`, `budget`, etc.).
   - `EDITABLE_SURFACES` permits adaptations solely on: `test_writer_guidance`, `implementer_guidance`, `planner_guidance`, `context_hints`, and `micromanager_context`.
2. **State Layout (`<state_dir>/harness/`)**:
   - `active_overlay.json`: active `revision`, `parent_revision`, `next_revision`, `state` (`"confirmed"` | `"probing"`), `probe_remaining`, `probe_baseline`, `probe_outcomes`, `active_entry_ids`, and `surfaces`.
   - `revisions/rev-XXXX.json`: immutable revision snapshots (`rev-0000.json`, `rev-0001.json`, ...).
   - `entries/<id>/EXPERIENCE.md` + `patch.json`: atomic per-entry Markdown card and JSON metadata (`stats`: `applied`, `helped`, `hurt`, `neutral`).
   - `INDEX.md`, `ledger.jsonl`, and `metrics.json`: rebuilt summary index, append-only event log (`card_outcome`, `lesson_added`, `revision_promoted`, `revision_confirmed`, `demotion`, `reset`), and computed efficiency metrics (`first_pass_rate`, `retry_recovery_rate`, `pass_rate`, `avg_attempts`, `avg_tokens_per_pass`, `avg_spend_per_pass`, `counter_fail_rate`, `harness_efficiency`).
3. **Dual Capture, Anti-Injection & Feedback Loops**:
   - `extract_contrast` extracts failure classes (`_classify_failure`) and scrubbed `evidence_pair` deltas (`_scrub_test_leaks` prevents assertion answer leaks), while `_deterministic_extract` captures fallback lessons even when `micromanager` is `"off"`.
   - When enabled, `Micromanager.reflect_harness` proposes lessons validated by `validate_harness_proposal` and `sanitize_lesson_text` (stripping edit markers, code fences, ANSI/OSC escapes, path traversals, and gate-bypass directives).
   - `openfarm run` shares one `HarnessLibrary` across cards so Card N updates Card N+1 immediately, retries dynamically re-query `select_guidance` with the latest `failure_class`, and persisted overlays reload across launches into fenced `harness adaptations` and `micromanager.harness_context`.
4. **Probe-Window Auto-Demotion & `Infra` Isolation**:
   - New revisions probe for `probe_window` non-`Infra` card outcomes and automatically roll back to `parent_revision` (`demote_reason = "probe_regression"`) when `pass_rate` or `harness_efficiency` regresses beyond `0.05` (with `auto_demote = true`).
   - `Infra` aborts never call `HarnessLibrary.record_card_outcome` or skew `metrics.json`.
   - `openfarm harness` exposes `status`, `index`, `show`, `promote`, `demote`, and `reset --yes`; with `--global` (v0.7), `status`, `promote` (restore) and `demote` (retire) act on the global library.
5. **Global Learning (v0.7)**:
   - Capture: the supervisor's reflection claims `scope`; the deterministic extractor claims `general`; `scope_of` checks a general claim against `project_markers` (no markers means `project`).
   - After each card, `flow.py` calls `report_to_global`: linked lessons report their scores; a lesson that hurt more than it helped is switched off here (`demote_reason = "global_veto"`) and the veto recorded; with `share = true`, a lesson passing `should_promote` and `global_eligibility` is added (refusals stored as `global_refused`).
   - At start, `sync_from_global` imports each active global lesson as a local candidate `exp-<gid>` with `origin = "global"`, which this project's own probe cycle and scores judge, and demotes retired ones (`demote_reason = "global_retired"`). `learn_from = "project"` imports nothing but still drops retired lessons.
   - Selection: `learn_from` filters by origin; on equal fit a project lesson ranks before a global one; one `max_cues_per_brief` covers both.
   - Bench runs set `OPENFARM_GLOBAL_HARNESS` to a folder inside the run, so they never read or change the owner's library; an arm may set `[harness]` `learn_from`, `share` and `global_dir`.

## Key v0.4 Pipeline & Gate Hardening

1. **ACP Micromanager & Security Isolation (`adapters/acp.py`, `micromanager.py`)**:
   - `initialize` sends `clientCapabilities: {}` so write (`fs/write_text_file`) and `terminal/*` capabilities are never advertised, and incoming write/terminal JSON-RPC requests return `-32601`.
   - `session/request_permission` denies write/execute tools and enforces `[micromanager] tool_policy` (`"none"` denies all tools; `"read-only"` permits read-only inspections strictly inside the session's own working folder via `resolves_within`, the adapter's folder when a session has none, excluding `never_touch` and `forbidden_files`; a request naming another session is rejected). This handler only sees what a standalone ACP server asks; openfarm's own bridges set the CLI's tools directly, and Codex and Antigravity children are held as in [How a child is held](#how-a-child-is-held).
   - `_sanitised_env` strips sensitive host env vars and, when `isolate_home = true`, points `$HOME` to a scratch directory with the login copied in from where the provider keeps it (`$CLAUDE_CONFIG_DIR` / `$CODEX_HOME` first, `$HOME` second), or from `[micromanager] auth_file` when provided. `[model] key_file` is never passed to ACP.
   - `strip_control_sequences` removes ANSI/OSC escape sequences and fences untrusted test/repo excerpts in prompts.
   - `scaffold_contract` may emit type stubs only; any production Rust `fn` body must be `todo!()` or `unimplemented!()`, and a TypeScript scaffold may hold only declarations and bodies that are exactly one `throw new Error(...)`.
   - Modes: `"off"` disables all calls; `"advisory"` logs decisions/recommendations without blocking or writing scaffolds/plans; `"active"` applies shaping/plans/scaffolds and can reject via `supervisor-reject` (`StopCode.SUPERVISOR_REJECT`).
2. **Phase A Fail-Before Retry Loop & Scaffolds**:
   - `test_writer` runs inside `test_writer_attempts` until generated tests compile against optional `scaffold_commit` (when `scaffold_contracts = true`) and fail for the right reason on the unimplemented codebase before entering Phase B.
3. **Checkpointed Phase B Execution**:
   - When `planner` (`"auto"` / `"on"`) or `shape_and_plan` emits `plan.steps`, Phase B commits intermediate checkpoints per step via atomic `apply_edits` while keeping `tests` and `test_edits` frozen.
4. **Gate Hardening**:
   - Formatting runs before `full_diff` capture and before `revert-check`.
   - `revert-check` compares cleanly against `base + frozen-tests` so frozen test changes do not pass falsely.
   - Cargo parser consumes split stdout/stderr streams and surfaces crash signals (`SIGSEGV`, `SIGABRT`, etc.).
   - Counter-tests run as new files, one at a time (Rust with `--test <stem>`), with the worktree restored exactly afterwards, supporting bounce-back (`adjudicate_checker` or the implementer) when counter-tests fail.
   - `breaker.json` keys circuit-breaker strikes by real sanitized card IDs (`_safe_id`).
   - `[state] min_free_mb` aborts before spawning worktrees on low disk space (`infra`).
   - `OpenAICompatibleBackend` retries transient HTTP `429` and `5xx` errors with backoff while enforcing `allowed_endpoints`.
